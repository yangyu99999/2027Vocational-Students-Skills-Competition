# 代码规范（本项目约定）

> 立于此轮重构（2026-10-31）：`main.c` 从 1056 行降到 ~220 行，业务逻辑拆进 `MDK-ARM/APP/`。

## 1. 分层，谁不许调谁

```
Core/                 CubeMX 生成：启动、时钟、外设 init、2ms 主循环调度（不要往里加业务）
  └─ USER CODE 段     只允许放：初始化顺序、主循环里对 APP 的 4 个调用
MDK-ARM/BSP/          驱动：只和寄存器/时序打交道，不认识"门""卡""密码"
MDK-ARM/APP/          业务：只调 BSP，不直接写 OLED/RC522/Flash 寄存器
Docs/                 文档、规范、差异说明
```

- `main.c` 只允许调 `APP` 层函数；`APP` 只允许调 `BSP`；`BSP` 不允许反向依赖 `APP`。
- 新功能先问"它属于哪一层"，再决定放哪个文件，禁止继续往 `main.c` 堆。

## 2. APP 层现有模块（按职责找位置）

| 模块 | 目录 | 职责 | 别往里放 |
|---|---|---|---|
| `CardStore` | `APP/CardStore/` | 卡表白名单：加/删/查/张数、AT24C16 优先 + 片内 Flash 兜底 | 界面文字、状态机 |
| `Ui` | `APP/Ui/` | 所有 OLED 输出：密码页、提示页、管理页、温度行、卡号行 | 业务判断、存储读写 |
| `Rfid` | `APP/Rfid/` | RC522 复位/配置/150ms 轮询，读到卡通过回调抛出 | 白名单判断、开门动作 |
| `Door` | `APP/Door/` | 门禁业务：密码、刷卡授权、加删卡、状态机、舵机、红绿灯 | 底层的 GPIO/I2C 细节 |
| `AppDef.h` | `APP/` | `DoorState`、`RfidView`、`APP_UID_LENGTH`、`APP_PASSWORD_LENGTH` | 可变状态 |

新增功能的默认落位：**屏上显示 → `Ui`；掉电保存 → `CardStore`；流程/状态 → `Door`；外设时序 → `BSP`。**

## 3. 写代码的硬性要求

1. **能封装就封装**：一个文件一个职责，超过 ~300 行就考虑拆；重复两次以上的代码抽函数。
2. **接口最小化**：头文件只放调用者需要的函数；其余一律 `static`。跨模块只走头文件函数，**不共享全局变量**。
3. **状态归自己**：谁的状态谁保存（`static` 在 .c 里），别人要看得调 `Xxx_GetView()` 这类接口。
4. **魔数集中**：角度、时间、密码、卡片容量、引脚相关常量放在该模块顶部宏里，并写清楚单位。
5. **一行注释起步**：每个函数上面写 `功能 / 参数 / 返回 / 条件`，与现有风格一致。
6. **不写"能跑就行"的临时分支**：加/删卡这类会写存储的操作，必须有回滚或成功校验。
7. **改完必须能编译**：至少跑通 `armcc` 单文件编译 + `armlink` 全量链接（见下方命令），并在交付说明里报体积。

## 4. 交付纪律（用户明确要求）

- **能优化就优化**；**不能优化时，直接说明原因**（例如：受 128×64 屏、RAM、Flash 寿命、硬件时序限制）。
- **如果强行优化会减少功能，必须先说，不许偷偷砍功能。**
- 改动要讲清楚：改了哪个文件、为什么、验证到什么程度、还差什么（例如需要上板验证）。
